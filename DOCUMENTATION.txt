1. OVERVIEW
-----------

This repository is a local development environment for Odoo 19 with a custom
application module that integrates Envia.com shipping services into Odoo.

Main capabilities:
  - Connect Odoo to Envia.com via OAuth (plugin setup wizard)
  - Quote shipping rates from multiple carriers
  - Create shipments and download labels
  - Track shipments (manual + scheduled cron sync)
  - Onboarding flow for first-time quote creation

Author:  Alejandro Prado
License: LGPL-3
Module:  envia (version 19.0.1.104.0)
Category: Inventory/Delivery


2. TECH STACK
-------------

  - Odoo 19 (Docker image: odoo:19)
  - PostgreSQL 16
  - Python 3 (Odoo runtime)
  - JavaScript / OWL (custom backend UI components)
  - Docker Compose for local development

4. LOCAL DEVELOPMENT SETUP
--------------------------

Prerequisites:
  - Docker and Docker Compose

Start the stack:
  docker compose up -d

Access:
  - Odoo UI:  http://localhost:8069
  - PostgreSQL: localhost:5433 (user: odoo, password: odoo)

Configuration files:
  - config/odoo.conf
      admin_passwd = admin
      addons_path  = /usr/lib/python3/dist-packages/odoo/addons,/mnt/extra-addons
  - ./addons is mounted to /mnt/extra-addons inside the Odoo container

Install the module:
  1. Create or select a database in Odoo
  2. Activate Developer Mode
  3. Apps > Update Apps List
  4. Search "Envia.com" and install

Envia OAuth / Eshop endpoints (docker-compose.yml):
  Development profile is active by default (x-envia-oauth-dev).
  To switch to production, comment the dev anchor and uncomment prod:

    <<: *envia-oauth-dev      # active
    # <<: *envia-oauth-prod   # inactive

  Environment variables injected into the Odoo container:
    ENVIA_OAUTH_INTEGRATION_URL
    ENVIA_OAUTH_POPUP_URL
    ENVIA_ESHOP_TEST_URL
    ENVIA_ESHOP_ACCESSES_ME_URL

6. DATA MODELS
--------------

Core models (envia.*):

  envia.quote
    Stores a shipping rate request and its results.
    States: draft | quoted | expired | used
    Links: sale.order, stock.picking, res.company
    Child: envia.quote.service (available carrier services)

  envia.quote.service
    Individual rate option returned by Envia API (carrier, price, ETA).

  envia.shipment
    Created shipment with tracking number, label, pricing.
    States: draft | created | in_transit | delivered | cancelled
    Inherits: mail.thread, mail.activity.mixin
    Child: envia.tracking.event

  envia.tracking.event
    Tracking history entries for a shipment.

  envia.carrier
    Reference data for supported carriers (codes: dhl, fedex, estafeta, etc.).

Extended Odoo models:

  res.company
    Envia configuration per company:
      - envia_environment (sandbox | production)
      - envia_api_token (shipping API Bearer token)
      - envia_base_url, envia_default_carriers
      - envia_default_origin_partner_id
      - envia_label_format (PDF | ZPL | PNG)
      - envia_label_size (STOCK_4X6 | PAPER_4X6)
      - envia_oauth_connected, envia_oauth_access_token
      - envia_integration_api_key, envia_shop_id, envia_plugin_version

  res.config.settings
    Settings UI for all company Envia fields + OAuth URLs + callback info.

  sale.order / stock.picking
    Smart buttons, Envia status fields, actions to quote and create shipments.

  onboarding.onboarding / onboarding.onboarding.step
    Custom onboarding panel for the "envia_quotes" route.


7. SERVICE LAYER (services/)
----------------------------

Pure Python layer (no ORM dependency in DTOs/adapters):

  envia_client.py
    HTTP client (GET/POST) with Bearer auth and Envia-specific error handling.

  envia_official_adapter.py
    Implements EnviaAdapterBase:
      - quote()        -> POST ship/rate/
      - create_shipment()
      - track()

  envia_adapter_base.py
    Abstract adapter interface.

  payload_mapper.py
    Maps Odoo records (quotes, partners, pickings) to/from DTOs.
    get_envia_adapter(company) factory.

  dto.py
    Dataclasses: QuoteRequest, QuoteResponse, QuoteService, Contact,
    CreateShipmentRequest/Response, TrackRequest/Response, etc.

  envia_oauth_client.py
    OAuth popup URL builder, eshop test/accesses endpoints, token refresh.

  envia_integration_callback.py
    Parses and applies POST /envia/integration/callback from Envia.com.
    Resolves database, authenticates Odoo API key, stores shipping token.

  envia_plugin_setup.py
    Generates Odoo API keys for Envia integration, pending setup queue,
    module version helpers.


8. MAIN WORKFLOWS
-----------------

8.1 Plugin connection (OAuth)
  1. User opens Settings > Envia Shipping (or post-install wizard if pending)
  2. EnviaPluginConnectWizard generates an Odoo API key via
     generate_integration_credentials()
  3. User clicks "Connect" -> opens Envia.com OAuth popup/tab
  4. Envia.com validates the connection and POSTs to:
       POST /envia/integration/callback
  5. Callback stores:
       - hash  -> envia_api_token (shipping Bearer token)
       - shop  -> envia_shop_id
       - OAuth session data on res.company
  6. Wizard state transitions: ready -> waiting_external -> success | error

8.2 Quote shipping rates
  1. From a Sale Order or Delivery (stock.picking), open "Get Envia Quote"
  2. EnviaQuoteWizard collects origin/destination, weight, dimensions
  3. PayloadMapper builds QuoteRequest -> EnviaOfficialAdapter.quote()
  4. Results saved as envia.quote + envia.quote.service records
  5. User selects a service -> quote.state = quoted

8.3 Create shipment (label)
  1. From a quoted order/picking, open "Create Envia Shipment"
  2. EnviaCreateShipmentWizard uses selected quote service
  3. Adapter calls Envia create-shipment endpoint
  4. envia.shipment created with tracking_number, label_url/PDF attachment
  5. Quote marked as used

8.4 Tracking
  - Manual: action_track_shipment on envia.shipment
  - Automatic: ir.cron "Envia: Sync Tracking" every 30 minutes
    calls envia.shipment._cron_sync_tracking()

8.5 Onboarding
  - Route: envia_quotes
  - Triggered on post_init_hook and when company is created
  - Guides user through first quote (EnviaQuoteOnboardingWizard)
  - Custom OWL list view (envia_quote_list) shows onboarding banner


9. HTTP ENDPOINTS
-----------------

  POST /envia/integration/callback
    Auth: none (CSRF disabled, save_session=False)
    Body: JSON from Envia.com integration
    Headers:
      Authorization: Bearer <odoo_api_key>  (recommended; required on multi-db servers)
    Query: ?db=<db_name> (included in build_callback_url; used by handler, not by Odoo routing)
    Server config (mandatory local + production):
      server_wide_modules = web,base,envia_http
      Do NOT add envia here (blocks uninstall). envia_http is the tiny bridge module.
      Restart Odoo after changing odoo.conf.
    Database resolution (automatic, no X-Odoo-Database header):
      1. ?db= or ?database= or JSON database/db field when provided
      2. Odoo API key scanned across allowed databases (res.users.apikeys + company key)
      3. In-memory map from Connect wizard (until Odoo restart)
      4. Single allowed database on the server (monodb)
    Handler: envia_http bridge -> EnviaIntegrationController.integration_callback

  Production checklist:
    1. addons/envia and addons/envia_http on addons_path
    2. server_wide_modules includes envia_http (see config/odoo.conf)
    3. web.base.url = public HTTPS URL (Settings > General Settings)
    4. proxy_mode = True when behind nginx/Cloudflare/load balancer
    5. Smoke test: curl -X POST https://<domain>/envia/integration/callback -> 401, not 404
    6. docker-compose: switch ENVIA_OAUTH_* anchor from dev to prod before go-live
